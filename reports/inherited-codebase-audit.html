Executive summary

A capable control plane in mid-migration. Do not trust the repo map.

Ciutatis is a civic fork of Paperclip. The V1 docs describe a small Express + Vite + PGlite board. The tree is a dual-stack product: Node/Postgres self-host plus Cloudflare Workers/D1 for ciutatis.com, with the operator UI living inside Next.js at /admin.

Budget hard-stop is real Civic labels, Paperclip APIs CI listens to master Checkout is not atomic
Overall call
Inherit, then freeze the map
Main concern
Wrong-branch CI + checkout
Best part
Company-scoped control loop
Weakest part
Docs, Docker, UI test gate
Treat AGENTS.md as historical. There is no ui/ package. Default DB is embedded PostgreSQL under ~/.paperclip. GitHub workflows target master while this fork’s default branch is main.

Architecture

One monorepo, two production runtimes, one civic vocabulary layered on Paperclip tables. Heartbeat orchestration still lives in a 9,720-line server module.

Self-host

CLI → Express server/ → packages/db (Postgres / embedded-postgres). Adapters and plugin host run in-process. Optional static UI from server/ui-dist.

Hosted ciutatis.com

Dispatcher → OpenNext ciutatis-web (landing + admin). admin.ciutatis.com/api/* → workers/api → D1. Manual wrangler deploy. npm release does not ship this stack.

Findings

Ordered by severity. Objection type is named so architecture is not filed as a docs nit.

P0 · rollout

CI and release listen to master; default branch is main

pr-verify.yml, pr-policy.yml, refresh-lockfile.yml, and release.yml filter branches: [master]. This environment’s default branch is main. Unless a leftover master still receives PRs, verification and canary publish do not run on this fork.

.github/workflows/pr-verify.yml:5 · release.yml:5
P0 · trust / implementation

Issue checkout is not atomic and skips company access

Spec requires conflict-safe single-assignee checkout. requestService.checkout updates by id only and ignores expected statuses. assertCheckoutOwner is a no-op. POST /issues/:id/checkout does not call assertCompanyAccess, unlike GET /issues/:id and release.

server/src/services/requestService.ts:254 · server/src/routes/issues.ts:712
P0 · ops

Dockerfile copies files that are not in the repository

Missing: scripts/docker-entrypoint.sh, packages/mcp-server/package.json, packages/adapters/acpx-local/package.json. The image still sets ENTRYPOINT ["docker-entrypoint.sh"]. Quickstart and ECS docs assume this build.

Dockerfile:23 · Dockerfile:59
P1 · architecture

Heartbeat is a 9.7k-line god module

Run lifecycle, adapter execute, liveness, continuations, and budget invocation checks meet in server/src/services/heartbeat.ts. Recovery is partially split; this file remains the highest change-risk hotspot.

server/src/services/heartbeat.ts (9720 lines)
P1 · architecture

Postgres and D1 schemas must be maintained in parallel

~66 Drizzle SQL migrations vs ~10 D1 migrations. Hosted apply is manual. No scheduled D1 backup. Workers API is a subset of Express (no routines, adapters, environments, issue-tree-control, …).

packages/db · packages/db-cloudflare · workers/api/src/routes/index.ts
P1 · product

Adapter story is inconsistent

hermes_local is in AGENT_ADAPTER_TYPES but unregistered. acpx_local is registered and always throws. Onboarding locks new agents to cloudflare_workers_ai, contrary to PRODUCT.md’s unopinionated runtime stance.

packages/shared/src/constants.ts:58 · OnboardingWizard.tsx:50
P1 · quality

Sixty landing tests and all e2e sit outside the default gate

vitest.config.ts does not include apps/landing. Playwright e2e is dispatch-only. Release smoke is not called from release.yml. The serialized runner still names eight test files that do not exist, including issues-service.test.ts.

vitest.config.ts · scripts/run-vitest-stable.mjs:23

pnpm lint is a stub; dual naming tax is permanent until a rename

Root lint exits 0. Civic TypeScript names alias Paperclip tables. Activity logging is real on many mutations, not on checkout. createIssueDetailPath is imported but not exported.

UX / UI handbook

Two products share @ciutatis/landing: a bilingual civic public site and a dense operator board. The live work object is RequestDetail, not the unrouted IssueDetail chat thread.

Shipped sidebar

New Request, Dashboard, Inbox, Requests, Objectives, optional Workspaces, Projects, Agents, Org, Costs, Activity, Settings. Company switching is the left rail, not the spec’s dropdown header.

apps/landing/src/admin/components/Sidebar.tsx

Spec gaps

No My Issues (file exists, unrouted), no Views, no notification bell. Light-first OKLCH tokens vs spec dark HSL. Onboarding cannot pick Claude/Codex. Keyboard: Cmd+K, C, [ / ].

doc/spec/ui.md · OnboardingWizard.tsx · useKeyboardShortcuts.ts

Operator loop

  1. Inbox for approvals and failed runs.
  2. C or New Request → list/kanban → /requests/:id.
  3. Comments and documents on RequestDetail; live run widget for execution.
  4. Costs for budget policies and incidents; AgentDetail for per-channel budget.
  5. Instance admin under /instance/settings for tenants, Cloudflare, plugins.

Orphans

Unrouted: MyIssues.tsx, Org.tsx, IssueDetail.tsx + IssueChatThread, several UX labs. Scrutiny is routed with “Coming soon” sections. IssueBlockedNotice and ProductivityReviewBadge import a missing createIssueDetailPath export.

Continue UI work in apps/landing/src/admin/. Use company-aware Link. Update DesignGuide when adding composites.

Recommendation

Path forward

Keep the control-plane model. Do not add features until CI points at the real default branch, checkout is gated and atomic, and Docker COPY/ENTRYPOINT match the tree. Then wire landing tests into pnpm test:run.

What to keep

Company scoping, budget hard-stop, Better Auth modes, adapter registry, plugin slot model, RequestDetail as the work surface, civic public site as a separate visual language.
